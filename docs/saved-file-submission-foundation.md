# 保存済み課題フォルダー提出：第1段階

保存だけでは提出にしない。将来の明示的な提出操作で、保存済みの通常ファイルを
一括提出する。本段階は対象識別と認可までであり、本文収集・送信・提出API・Git
スナップショット・拡張機能・Vue・Linux環境操作は追加しない。

## TaskとProjectの互換性

`TaskSubmissionTarget`を別表として追加する。Taskに新しい列や自動ロード関係を
追加しないので、既存TaskのCRUD・レスポンスと、005適用前の既存APIは変わらない。
未登録Taskは提出対象へ自動変換しない。1 Taskは最大1 Project・1提出対象学生・
1相対フォルダーに対応する。ルートは将来の管理側providerがUser×Project単位で
供給する。絶対パスやroot FDをHTTP要求で指定させない。

登録はチーム所有者だけに許可し、対象学生の現在所属とTaskの担当者を照合する。
登録・解決サービスは既存Firebase認証で確定したUserを受け取る内部サービスであり、
actorを要求本文から作ってはいけない。`create_submission_target_resolver`は既存の
`get_project_team_member`/`get_accessible_project`をDependsで再利用する接続部であり、
今回は実APIに登録しない。単独のUser ID入力を認証済みとみなす機能はない。

現行Task更新APIはチームメンバーが担当者を変更できる。この挙動は変更しない。
そのため提出許可には、現在のTask担当者と所有者登録済みstudent_idの両一致を要求する。
旧APIで自分を担当者にしても提出権限は獲得できない。所有者にも他学生の提出権限はない。
未割当・所属取消し・対応不整合は拒否する。担当者変更後の再登録手順は今後定義し、
今回は既存対応の自動上書きや再紐付けを行わない。

## フォルダー識別

NFC/POSIX正規形の相対パスだけを受理する。空要素、`.`/`..`、絶対パス、Windows/UNC、
バックスラッシュ、コロン、制御文字、隠し要素、過大なパスを拒否し、危険な入力を
黙って短縮・URLデコード・正規化しない。同一Project・学生の重複/包含フォルダーも拒否する。
登録サービスはProject行をロックし、呼出し元がcommit/rollbackするまで保持する。

`open_submission_folder`は管理側が保持するroot FDの複製から、各要素を
O_DIRECTORY/O_NOFOLLOW・dir_fd指定で開く。User×Project、device/inode、所有者、
書込み権限、操作直前の全FD同一性を確認し、返却後に所有FDだけを閉じる。
本文は読まない。Windowsの既定実装は拒否する。テストは合成FDだけを使用する。
実ルートproviderは未接続であり、code-serverの保存領域をProjectStorageへ直接マウントしない。
この束縛は継続的な操作許可ではない。将来の収集・提出では認可を操作時に再解決し、
書込み競合や認可取消しも再確認する。完全な原子的フォルダースナップショットや、
特権者によるmount変更への保証は本段階では提供しない。

## DB移行と未実装部分

`backend/migrations/005_task_submission_targets.sql`を明示的に用意したが、実DBには
適用しない。既存行・列を変更しない。新表は起動時自動作成から除外する。
同名表がある場合は停止する一度限りの移行であり、自動修復しない。
FKは存在性を検証し、Team/担当者/正規パスの整合はサービスで検証する。
Task削除時だけ対応をCASCADE削除する。提出履歴はまだない。

テストはSQLiteメモリDBと偽FDを使い、Firebaseの外部検証だけを代替する。
PostgreSQLへの005の適用、複数プロセスのロック競合、実LinuxのFD走査は未検証。
保存済みファイル提出API、短期提出許可、収集、冪等性、進捗反映は次段階で実装する。
既存の検証拡張・A2/B1/SSH255の記録は変更しない。
